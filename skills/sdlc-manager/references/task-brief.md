# Task brief

Use this for substantial work that needs a durable shared record. Adapt it to the repository's existing issue or planning format.

- **Outcome:** What should a user or operator be able to do?
- **Context and evidence:** Relevant files, issue, reproduction, or research.
- **Reused knowledge:** Relevant note IDs, freshness/coverage limits, and facts still needing inspection.
- **Acceptance:** Stable IDs for observable success and important failure cases.
- **Scope:** Included changes and explicit exclusions.
- **Constraints:** Compatibility, data, accessibility, performance, deadlines.
- **Assumptions or decisions:** Facts established, decisions made, material unknowns.
- **Work ownership:** Task ID, specialist, allowed files, dependencies, acceptance status.
- **Interface agreement:** Relevant data shapes, permission/error behavior, compatibility, revision and consumers.
- **Verification:** Commands or scenarios drawn from this repository; results as completed.
- **Release implications:** Only when relevant: migration, rollout, rollback, monitoring.
- **Status:** Complete, in progress, or blocked, with evidence and next owner.

When resuming, inspect the current working tree and note which evidence still
applies. Update one shared record through its designated owner rather than having
every specialist append conflicting status files.
